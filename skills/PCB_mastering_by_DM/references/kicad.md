# Операции KiCad

Используй доступные анализаторы/парсеры и установленный `kicad-cli`; проверяй версию и `--help`, а не жёсткий путь с другого компьютера. Для S-expressions используй детерминированный parser, не `eval`. Для сравнений экспортируй производные в рабочий каталог, исходники сохраняй.

Полезные операции, когда они соответствуют поручению:

```sh
kicad-cli sch export netlist --help
kicad-cli sch export pdf --help
kicad-cli pcb export stats --help
kicad-cli pcb export ipcd356 --help
kicad-cli pcb export svg --help
kicad-cli pcb drc --help
```

Свежий netlist сравнивай с supplied snapshot по resolved Values/footprints и pin→net. Сырой анализатор может оставить `${ALTIUM_VALUE}` или выбрать неправильное конфликтующее MPN-поле; сверяй elevated findings с raw и экспортом.

В KiCad 10 nets могут задаваться строками, в прежних версиях — числовыми IDs. Pad coordinates локальны к footprint; учитывай angle/side при преобразовании. Различай zone boundary и сохранённые filled polygons. Не выводи фактическое наличие меди из одного boundary.

Для scoped сравнения запускай DRC без сохранения/перезаливки исходника; отмечай, если проверены существующие fills. Если задача требует refill/исправлений, работай с разрешённой рабочей копией и проверяй итог отдельно. Пустой `schematic_parity[]` не означает выполненную проверку: фиксируй, запускался ли parity и какая схема использована.

SVG/PDF — реальные производные native файла. Подписывай layers, side, view direction и crop; bottom view может быть немиррорным top view. Если расширяешь viewport для отверстия у края, меняй только окно просмотра, сохраняя графику и записав преобразование. Не восполняй неизвестную разводку изображением, сгенерированным AI.

Для Altium эти CLI-команды неприменимы. Используй доступный native интерфейс либо экспорты; отсутствие инструмента редактирования означает ограничение операции, а не невозможность инженерного анализа.

## Согласованность финальной поставки

После последней правки сначала синхронизируй локальные символы/footprints, разрешённые значения/MPN, BOM и placement-метаданные; затем заново экспортируй netlist и нужные native виды. Для DRC/parity сохрани точную команду, версию KiCad, используемую схему и хеши входов. Пустой результат без признака выполненной проверки имеет статус «не проверено».

Проверяй нумерованные NC по свежей схеме и их физическим pads. Считай отдельно применённые NC, висящие маркеры и netless pads. Для EP требуется паспорт точного корпуса; native pad сам по себе не подтверждает его существование у детали. Не скрывай library mismatch, если поставляемая библиотека расходится с финальной платой.

Финальный отчёт формируется после проверок и содержит их хеши. Если затем менялся CAD, пересчитай затронутые проверки; не обновляй лишь хеши старого отчёта.


Для ремонта геометрии выполняй [pcb-geometry.md](pcb-geometry.md): реальные effective copper/hole shapes, все SMD без фильтра по сети, сохранность широких участков и соседних возвратов. Не меняй глобальные подстроки чисел. Native DRC с refill/parity проверяй отдельно по violations/unconnected/parity-executed; после сохранённого refill перечитай копию, затем запускай guards и экспортируй окончательные виды. Одна смена хеша в отчёте не делает старый запуск актуальным.
